# 第一阶段需求与边界

## 目标

在本地完成可演示的协作闭环：注册/登录 → 创建项目 → 向已注册成员发送邀请 → 对方接受 → 创建及分配任务 → 任务执行人提交成果 → 项目负责人验收。第一阶段不接入大模型，以便先验证数据与权限。

## 角色与权限

| 操作 | 项目负责人 | 普通成员 | 非成员 |
| --- | --- | --- | --- |
| 查看项目与任务 | 是 | 是 | 否 |
| 修改项目、邀请成员 | 是 | 否 | 否 |
| 删除项目 | 是 | 否 | 否 |
| 退出项目 | 先转让项目负责人角色 | 是 | 否 |
| 创建、编辑、分配任务 | 是 | 否 | 否 |
| 推进本人任务、提交成果 | 是（本人任务） | 是（本人任务） | 否 |
| 验收或驳回成果 | 是 | 否 | 否 |

一个项目只有一个项目负责人；邀请对象须先注册且账号有效。受邀人接受后才成为成员，也可以拒绝；项目负责人可以撤销待处理邀请。任务可暂不指定执行人。项目负责人可以将任务分配给项目成员担任任务执行人。项目名称和任务标题须包含非空格字符。

项目删除与成员退出在前端均需经过后果提示和输入项目名称的二次确认；后端还需验证提交的项目名称，并分别验证项目负责人或成员权限。删除项目会永久删除其成员、任务、成果和验收记录。成员退出后失去项目访问权限，未完成任务退回未分配，已完成任务保留原任务执行人姓名。项目创建和删除写入独立的管理员通知，管理员可逐条标为已读。

系统管理员可以新增、停用、恢复用户；停用用户无法登录，但历史记录保留，其未完成任务退回未分配。若停用的用户是项目负责人，管理员必须指定有效的接任项目负责人。用户可编辑姓名并上传头像（JPEG、PNG、WebP，最大 2 MB）。

## 任务状态

`todo` → `in_progress` → `review` → `done`。项目负责人驳回 `review` 后回到 `in_progress`。任务执行人提交成果时必须填写链接或说明；验收与驳回均记录操作人、时间和说明。删除任务仅允许项目负责人执行。

## 第二阶段及之后

成员技能画像已实现：用户自行填写每周可投入时间（0～80 小时）、学习目标和最多 20 项技能及熟练度（1～5 级）；项目负责人可查看项目成员画像，普通成员不能查看其他人的画像。任务权重评估已实现确定性规则建议、项目负责人确认与调整原因记录；建议分值与确认分值分开保存。AI 任务拆解已实现项目需求输入、结构化草稿生成、项目负责人编辑与确认；任务依赖有项目边界和循环检查，前置任务未完成时不能开始后续任务。AI 分工建议已实现基于成员画像和任务数据的推荐草稿、项目负责人改选任务执行人及确认。进度诊断已实现规则风险识别、AI 总结与报告快照留存。数据分析页已实现任务状态、成员工作量、已确认权重、近 14 天完成趋势的 ECharts 图表，以及截止日期安排。后续进入整体流程验收、部署和课程文档整理。AI 输出保留依据和原始建议；关键写操作须经用户确认和权限检查。

## 验收场景

三名学生注册；甲创建项目并邀请乙、丙；乙接受、丙拒绝；甲创建任务并分配给乙；乙提交成果；甲驳回一次，乙修改后再次提交，甲验收通过；丙不能查看项目、修改或验收乙的任务。管理员可新增与停用用户；用户能更新姓名和头像。
