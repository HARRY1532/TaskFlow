# TaskFlow AI

面向高校课程项目的协作管理系统。当前阶段提供用户认证、系统管理员用户管理、项目邀请确认、个人信息与头像、成员技能画像、任务权重评估、AI 任务拆解、AI 分工建议、项目进度诊断、数据分析图表、任务看板及成果验收。项目负责人管理项目并验收任务，任务执行人执行和提交所分配的任务。AI 只提出可解释的建议，项目负责人确认后才写入关键业务数据。

## 本地启动

需要 Node.js、npm 和 Python 3.11+。**每段命令的第一行会切换到对应项目目录**；请整段复制执行，不要在 `F:\` 目录直接运行后续命令。当前工作区已创建 `backend/.venv` 和 `backend/.env`，重复执行不会覆盖它们。Windows 上若 `python` 命中 WindowsApps 别名，请使用真实解释器路径。

```powershell
Set-Location F:\TaskFlow\backend
if (-not (Test-Path .venv\Scripts\python.exe)) { & F:\python\python.exe -m venv .venv }
& .\.venv\Scripts\python.exe -m pip install -e '.[dev]'
if (-not (Test-Path .env)) {
    $secret = & .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
    (Get-Content .env.example) -replace '^JWT_SECRET_KEY=.*$', "JWT_SECRET_KEY=$secret" | Set-Content .env -Encoding utf8
}
& .\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

另开终端：

```powershell
Set-Location F:\TaskFlow\frontend
npm.cmd install
npm.cmd run dev
```

后端接口文档：`http://127.0.0.1:8000/docs`。前端开发服务器地址以 Vite 控制台输出为准。

### 启用 AI 功能

在 [DeepSeek 开放平台](https://platform.deepseek.com/) 获取 API Key，并在 `backend/.env` 中新增 `DEEPSEEK_API_KEY=你的密钥`，然后重启后端。AI 任务拆解、智能分工和进度报告使用 `deepseek-flash` 模型。API Key 仅保存在后端环境变量中，不要填入前端页面或提交到 Git。未配置 Key 时，AI 生成操作会提示服务未配置；进度页面的规则快照和其他功能仍可使用。已有 `backend/.env` 的用户需要手动新增这一行；`OPENAI_API_KEY` 不再用于 AI 功能。

项目负责人在项目看板点击“AI 任务拆解”，先保存项目目标和详细需求，再生成任务草稿。草稿包含任务描述、验收条件、预计工时、所需技能和建议依赖。项目负责人可以修改、取消选择某些任务并调整依赖，点击“确认所选任务并创建”后才会写入任务。草稿原文与创建记录会保留；已确认草稿不能重复创建。任务依赖必须在同一项目中，不能形成循环；前置任务未完成时，后续任务不能开始。

项目负责人可点击“AI 智能分工”，对待开始且未分配的任务生成执行人建议。每次最多分析 20 项任务，结合成员技能、学习目标、每周可用时间、已有任务工时和任务权重给出推荐与风险提示。项目负责人可跳过任务或改选任务执行人，确认后才实际分配；草稿及原始推荐保留。任务或成员发生变化时，后端重新检查状态和权限，不会盲目应用旧草稿。若成员没有填写画像，系统会明确标记为未知，不将其当作零能力。

项目负责人可在项目看板点击“进度诊断”。当前快照按北京时间计算任务完成率，并识别逾期、即将到期、前置任务阻塞、未分配、缺少成果记录和工作量集中的情况；无需 API Key 即可查看。点击“生成 AI 报告”后，DeepSeek 根据快照生成总结与调整建议，报告连同当时的快照保存，便于回看。报告只提供建议，不自动修改任务。

所有项目成员可在项目看板点击“数据分析”，查看任务状态、成员任务数量及预计工时、已确认任务权重、近 14 天完成趋势和按截止日期排序的任务安排。图表使用 ECharts，数据由后端按项目权限实时汇总，不需要 API Key。趋势根据当前仍存在的任务及其创建、验收事件计算；删除任务会连同任务事件一起移除，因此趋势图不代表完整历史审计记录。任务没有可靠的开始日期，时间安排采用截止日期清单。预计工时是任务总估计，不代表本周投入时间，也不用于个人成绩评定。

## 首次设置系统管理员

先在页面注册管理员账号，再在本机终端执行以下命令。该命令只授予指定的已注册账号系统管理员权限，不会创建默认密码；普通用户无法通过注册接口自行获得管理员权限。

```powershell
Set-Location F:\TaskFlow\backend
& .\.venv\Scripts\python.exe -m app.cli promote-admin your-email@example.com
```

管理员可在“用户管理”页新增、停用和恢复账号。停用保留历史记录，并将该用户未完成的任务退回未分配；若目标用户是项目负责人，停用时需要指定接任项目负责人，其负责的项目会一并移交。项目负责人发起邀请后，受邀用户须在“项目邀请”页接受，才会成为成员。

项目负责人可以删除项目；删除会永久移除该项目的成员、任务、成果与验收记录。普通成员可以退出项目；未完成的本人任务会退回未分配，项目负责人需先转让角色才能退出。删除和退出都要求两次弹窗确认，第二次需输入项目名称。管理员可在“用户管理”页按姓名或邮箱搜索用户，进入用户详情查看该用户创建与删除项目的记录；记录时间显示为北京时间，删除记录不会随项目一起消失。

登录后可在“个人信息”页修改姓名、头像和密码。若使用临时密码初始化管理员账号，请首次登录后在此修改密码，并删除本地临时密码文件。
登录后也可在“个人信息”页填写每周可投入时间、学习目标和技能熟练度（1～5 级）。项目负责人在项目页可查看本项目成员的画像；普通成员只能查看和修改自己的画像。现有 SQLite 数据库启动时会自动创建画像表。
项目负责人可在任务卡片点击“评估权重”，填写技术复杂度、预计工时、项目重要性和实现风险，先计算规则建议，再确认或调整分值后保存。调整分值必须说明原因；项目成员可查看已确认的分值。分值用于任务规划，不代表成员贡献或成绩。规则为复杂度×6、预计工时按最多 40 小时折算 30 分、重要性×5、风险×3，最高 100 分。

## 开发辅助流程

任务卡片新增“开发清单”：项目负责人或任务执行人可调用 DeepSeek，根据任务描述、验收条件和项目技术栈生成实现与测试建议。任务执行人在任务进行中可勾选并保存进度；重新生成会覆盖原清单，页面会先提示确认。生成开发清单时不读取仓库代码，也不会自动验证清单是否完成。

项目负责人可以在项目页绑定一个公开 GitHub 仓库。系统通过 GitHub 官方 API 核对仓库是否公开，绑定后任务执行人提交代码链接时，链接必须指向该仓库的 PR 或提交详情。后端读取标题、作者、状态、提交 SHA 和核验时间，并在任务卡片展示；项目负责人或任务执行人可以手动刷新。代码信息是最后一次核验的快照，不代表代码质量、测试通过或满足验收条件。测试记录链接和测试说明仍由成员填写，项目负责人据此人工验收。未绑定仓库的项目仍可手动填写代码链接，但不会核验。已有任务记录会在后端启动时自动补齐新增字段。

公开仓库读取不需要 GitHub 令牌，但会受到 GitHub API 请求频率限制；受限或网络异常时，绑定或核验会提示稍后重试，不会把未经核验的链接标为已核验。当前不支持私有仓库、GitHub Actions 结果自动核验或自动通过验收。

待验收任务关联公开 PR 后，项目负责人可以点击“PR 改动证据”并主动读取文件改动。后端只接收该仓库 PR 的最多 20 个文件、总计最多 16000 字符的文本补丁；超限会拒绝保存，缺少文本补丁的文件会要求人工查看。改动快照保存在本地数据库，项目成员可回看；任务内容或已核验代码 SHA 变化时，旧快照会标记为非当前。

项目负责人查看快照后，可点击“生成 AI 验收建议”。页面会连续显示两次信息安全确认，第二次需输入“发送至 DeepSeek”。后端再次确认负责人权限、待验收状态、快照版本和确认信息，并对即将发送的内容做常见密钥模式预检。通过后仅发送任务标题与描述、验收条件、开发清单、测试说明、PR 标题、文件路径和有限文本补丁，不发送邮箱、头像或 API Key。AI 输出包含有相关代码证据的点、证据不足的点和建议人工执行的测试；项目负责人仍负责验收。项目成员可回看已保存的建议。

敏感信息预检可能遗漏。模型被要求发现疑似泄露时立即警告、停止分析且不复述敏感值；此时本系统不保存该次 AI 回复，也不启用 Agents SDK 跟踪。根据 [DeepSeek Responses API 文档](https://api-docs.deepseek.com/api/create-response/)，接口无会话状态，不在服务端保存会话；但本系统无法验证或删除服务方其他日志、缓存，也无法撤回已发送请求。请在发送前人工检查补丁；若发现真实密钥泄露，应立即轮换。

## 开发原则

- 项目数据仅向项目成员开放；任务变更由后端验证成员身份。
- 项目负责人管理成员和验收任务；任务执行人完成并提交任务成果；AI 不直接修改任务或评价个人成绩。
- 项目名称和任务标题不能只包含空格。
- 数据库文件、密钥、虚拟环境及依赖目录不提交到 Git。
